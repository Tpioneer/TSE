# 8 ms CPU 分块实测

同一段 Mini LibriSpeech 双人混音有 64,053 个输入样本（4.0033 秒）。官方整段和各 BSRNN 流式路径都产生 64,000 个样本。比较覆盖开头、稳态和 flush，保持同一注册语音、种子和增益，无移位搜索。官方整段对目标干净语音的 SI-SDR 为 14.6087 dB。以下数字均来自 Intel Core Ultra 5 125H 的 CPU 单流，系统负载和线程调度未固定。

| 模型与执行方式 | RTF 中位数 | 节拍投喂首包 ms | 回调 P95 ms | 最大绝对误差 / RMS | 对官方输出 SNR dB | 对目标 SI-SDR dB | 与官方差值 dB |
|---|---:|---:|---:|---|---:|---:|---:|
| PyTorch FP32，2 线程，原 PR 基线 | 30.344 | 499.5 | 368.4 | 3.58e-7 / 2.26e-8 | 133.56 | 14.61 | ≈0 |
| OpenVINO FP32，8 线程，逐帧 | 7.868 | 192.8 | 110.0 | 2.98e-7 / 3.22e-8 | 130.47 | 14.6087 | −0.000001 |
| ORT 动态 INT8，2 线程，逐帧 | **4.973** | 157.7 | 67.3 | 0.01192 / 0.0008833 | 41.70 | **14.7295** | +0.1208 |
| ORT INT8，每 4 帧更新掩码 | 1.726 | 82.7 | 56.2 | 0.57180 / 0.06557 | 4.29 | 2.2720 | −12.3367 |
| ORT INT8，每 8 帧更新掩码 | **0.512** | 53.5 | **27.7** | 0.39695 / 0.06943 | 3.80 | **1.4916** | **−13.1171** |

原 PR 的 PyTorch 目标分数用同一段官方整段结果近似，波形等价误差另列。逐帧模式中最快的实测为 ORT INT8，仍高于实时预算。每 8 帧更新的模式三轮 RTF 为 0.685、0.512、0.493，只在更新帧运行分离器并推进 LSTM，其余帧用最近掩码处理当前复谱。它可以按 128 样本返回波形，但改变了模型，在有更新的回调仍可超过 8 ms。这段音频的质量损失使它不适合作为可听波形的默认路径。单条音频上逐帧 INT8 的正向 SI-SDR 差异不能推断为量化普遍提升质量。

## 耗时分布与优化

PyTorch 2 线程先输入 1024 个样本预热，再连续输入 32 个 128 样本块。对互不重叠的模块挂同步计时钩子，每帧总耗时 211.23 ms。下表是带钩子的诊断结果，和三轮无钩子的整段 RTF 分开报告。

| 阶段 | ms / 帧 | 占比 |
|---|---:|---:|
| 六层跨频带双向 LSTM | 97.01 | 45.9% |
| 32 个子带的掩码头 | 64.96 | 30.8% |
| 六层时序 LSTM | 21.91 | 10.4% |
| 输入子带处理 | 5.78 | 2.7% |
| 时序归一化与投影 | 4.55 | 2.2% |
| 频带归一化与投影 | 4.39 | 2.1% |
| 注册融合 | 0.70 | 0.3% |
| FFT、OLA、Python 调度及其它 | 11.93 | 5.6% |

将输入定为一帧，将 32 个掩码头、时序门计算与频带 BiLSTM 放入编译图，移除各子带单独进入 Python 模块的开销。注册门值在建立音流时算一次。INT8 对每帧内部的矩阵乘及六个跨频 LSTM 做动态量化，传递给下一帧的 12 个 h/c 张量仍为 FP32。确定性后缀测试在量化前后都成立。

## 前视与时延

每条路径共享 512 点 Hann 窗、128 点帧移、两端 reflect 和 OLA。跨频双向循环仅访问当前帧的 32 个频带，时间 LSTM 仅访问当前帧和以前的状态。输出 hop 起点为 k，读到 k+512 个输入样本时可得到完整的 [k,k+128)。hop 末端的前视界限是 384 样本（24 ms），单样点上界是 511 样本（31.94 ms）。两种降低更新频率的路径仅复用过去的掩码。所有配置都在收到第 512 个样本时开始提交首个 hop。

分别在样本 5333、8000、10683、12127 处替换未来波形。四个受保护前缀长度为 4864、7552、10240、11648，所有配置的前缀最大绝对差均为 **0**，且其后均检测到变化。原始记录见同目录的 `cpu_*_k*.json`。

RTF 包含建立每条音流的状态、全部同步 push、flush 和拼接。排除模型加载、图编译、已有注册向量的计算、磁盘 I/O 及人为等待。每配置预热后开三条独立音流；首包另用实时节拍实际投喂。P95 为有输出的满长回调，不包含 flush。OpenVINO 建图编译与 ORT 会话初始化在本次运行分别约 7.45 秒与 1.03 秒（含后端导入）。

## 替代权重的同音频对照

第三方 Open VoiceFilter-Lite 0.2.0 使用同一份单麦混音和注册，保留发布包的 160 样本（10 ms）原生接口。输入尾部补零排空，对照目标时只补偿源码确定的固定偏移 `n_fft - hop = 1040` 个样本（65 ms），不搜索最优偏移。三轮 RTF 为 0.382、0.429、0.378。目标 SI-SDR 为 0.096 dB，原混音为 0.139 dB，改善量 −0.044 dB。对这条音频，没有观察到值得用额外时延换取的分离收益。这里的 RTF 不可视为 BSRNN 的 8 ms 实测。[第三方发布包](https://pypi.org/project/open-voicefilter-lite/0.2.0/)

运行 `python -m pip install open-voicefilter-lite==0.2.0 librosa==0.11.0` 后使用 `python benchmark_voicefilter.py` 复测。脚本使用已安装的 ORT CPU、单线程 OpenBLAS，ORT 会话线程由第三方库默认设置。详见[各模型的输入、权重和时延](../research/低延迟候选.md)。

针对逐帧速度，还做了两个短探针。将分析、六个递归块和掩码头拆到不同线程，OpenVINO FP32 的频谱流水约 15.7 ms/hop，ORT INT8 七级流水约 14.0 ms/hop。两者均高于 8 ms，而且这里尚未计波形 I/O 和最终排空以外的应用开销。自写 AVX-VNNI 单线程矩阵乘的短测也未优于通用后端。上述探针仅用于淘汰实现方向，未计入同音频验收表。
